## تست‌های انجام‌شده در این شاخه (غیرتولیدی)

- `npm test --prefix scripts/cart-tests`: **۱۱ تست DOM جاوااسکریپت** روی SSR، سه/چهار ردیف، مجموع واحدها، GET خالی/ناقص یا دیرهنگام، محافظت کش نسخهٔ صفحه، انتخاب variation، روت‌های افزودن/حذف/تعداد/کد تخفیف و nonce. اجرای آن‌ها **بدون درخواست به سایت زنده** است.
- `php scripts/cart-tests/cart_contract.php`: **۲۳ assertion** اجرای کد واقعی PHP سبد با بدل‌های حداقلی WordPress/WooCommerce؛ اضافه‌کردن سه محصول و بیش از دو واحد، انتخاب variation و ردِ مقدار نامعتبر، ذخیرهٔ نشست، SSR، کوکی، تخفیف، رد هش خراب raw و عدم تأثیر روی افزونه‌های دیگر. این آزمون **جایگزین WooCommerce واقعی یا مرورگر واقعی نیست**.
- `python3 -m unittest discover -s scripts/tests -q`: **۱۹ تست** رگرسیون gate انتشار، ممنوعیت برگشت `cart-probe` و جلوگیری از انتشار نسخهٔ برابر/قدیمی‌تر از نسخهٔ زندهٔ مشاهده‌شده.
- `python3 scripts/build_release.py && python3 scripts/verify_release_safety.py`: ZIP بازتولیدپذیر **۱۳۱ فایل** از کل سورس و تطابق فایل‌ها/نسخه‌ها/CRC/SHA؛ SHA-256 نامزد 412: `9b7531b04b17f533d6d7d3a9ab2818140f3e8fb48bb3a5b546786c09dc879f53`. خروجی نامزد در `public/` فقط برای تست محلی ساخته شد؛ فایل‌های `public/` که از پیش در Git دنبال می‌شدند پس از تست بازگردانده شدند و ZIP نامزد commit نمی‌شود.
- [GitHub Actions، اجرای سبز `36230380998`](https://github.com/emeliijaddd-png/alookhor-update-publisher/actions/runs/36230380998): در **WordPress 6.8 + WooCommerce 10.2.0 واقعی** با MySQL موقتی، ZIP کامل 405 با SHA ثابت نصب/فعال شد. نخست مسیر هستهٔ وردپرس برای **Upload Plugin → Replace current** با ZIP محلی 412 اجرا شد؛ سپس در نصب موقتِ ازنو 405، مسیر واقعی `Plugin_Upgrader::upgrade()` با مانیفست و دانلود HTTPS شبیه‌سازی‌شده اجرا شد: ZIP خراب **پیش از جایگزینی** توسط hook نسخهٔ 405 رد و فایل موقت حذف شد، سپس ZIP سالم 412 نصب شد. در هر دو مسیر **تمام ۱۳۱ فایل نصب‌شده بایت‌به‌بایت با ZIP نامزد برابر** و افزونه در اجرای تازه فعال بود؛ فایل probe مخرب دیگر وجود نداشت. این آزمون‌ها **اتصال و پیشنهاد واقعی کانال آنلاین را اثبات نمی‌کنند**؛ بایت‌های manifest/download در مرز HTTP وردپرس mock شدند و فقط خواندن ZIP مرجع از GitHub واقعی بود.
- در همان اجرای سبز، درخواست‌های HTTP مستقل با کوکی مهمان سه محصول ساده، انتخاب variation واقعی برای پیشنهاد چهارم، چهار ردیف SSR، شمارش درست نشان هدر **قبل از JS**، تغییر تعداد تا ۸ واحد و حذف را پاس کردند؛ **مرورگر واقعی Chromium** پس از تأخیر/بازخوانی نیز نگهداری چهار ردیف، کلیک پیشنهاد متغیر، تعداد و حذف را تأیید کرد. `build` و `cart-wordpress` موفق؛ `deploy` و `diagnose` اجرا نشدند. هیچ سفارش، نصب تولیدی یا POST به سایت زنده انجام نشد. این CI هنگام tag نیز پیش‌نیاز deploy است.

## مانع «آمادهٔ نصب» و گام بعدی

**فعلاً دکمهٔ Update (به‌خصوص 411) یا Merge PR را نزنید.** انتشار با push این شاخه خودکار نیست؛ `release.json` عمداً `draft` است و workflow فقط build/test می‌کند. ZIP مرجع 405 به‌صورت پیش‌فرض مانیفست GitHub **شاخهٔ دیگری** را می‌خواند؛ push این PR آن مانیفست را تغییر نمی‌دهد. `main` درخت ناقص و workflow استقرار مستقیم از push داشته و مانیفست عمومی دیگرش اکنون 411 را تبلیغ می‌کند. دو مسیر نصب **Upload Plugin/Replace** و **Plugin_Upgrader** در WordPress موقت با موفقیت آزموده شده‌اند، اما این یعنی *بسته قابل نصب در تست است*، نه اینکه Update واقعی سایت به 412 اشاره می‌کند.

پیش از اعلام آماده‌بودن نهایی باید هویت نسخه و فایل‌های PHP نصب‌شده را فقط‌خواندنی تأیید کنیم؛ رفتار **قالب/کش واقعی و مرورگر** را برای افزودن/تعداد/حذف/پیشنهاد متغیر در محیط جدا از تولید بسنجیم؛ و برای دکمهٔ Update، ZIP 412 با SHA نهایی را روی **کانال واقعاً پیکربندی‌شدهٔ وردپرس** قابل دریافت و مستقل بررسی کنیم. گزینهٔ دستیِ Replace فقط با دانلود ZIP همین ساختِ آزموده‌شده و شناخت محدودیت‌های فوق قابل بررسی است؛ هنوز توصیهٔ نصب تولیدی نشده است. این شاخه هیچ سفارش، تست POST روی سایت، نصب یا انتشار تولیدی انجام نداده است.
