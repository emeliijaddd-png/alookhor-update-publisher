## تست‌های انجام‌شده در این شاخه (غیرتولیدی)

- `npm test --prefix scripts/cart-tests`: **۱۱ تست DOM جاوااسکریپت** روی SSR، سه/چهار ردیف، مجموع واحدها، GET خالی/ناقص یا دیرهنگام، محافظت کش نسخهٔ صفحه، انتخاب variation، روت‌های افزودن/حذف/تعداد/کد تخفیف و nonce. اجرای آن‌ها **بدون درخواست به سایت زنده** است.
- `php scripts/cart-tests/cart_contract.php`: **۲۳ assertion** اجرای کد واقعی PHP سبد با بدل‌های حداقلی WordPress/WooCommerce؛ اضافه‌کردن سه محصول و بیش از دو واحد، انتخاب variation و ردِ مقدار نامعتبر، ذخیرهٔ نشست، SSR، کوکی، تخفیف، رد هش خراب raw و عدم تأثیر روی افزونه‌های دیگر. این آزمون **جایگزین WooCommerce واقعی یا مرورگر واقعی نیست**.
- `python3 -m unittest discover -s scripts/tests -q`: **۱۹ تست** رگرسیون gate انتشار، ممنوعیت برگشت `cart-probe` و جلوگیری از انتشار نسخهٔ برابر/قدیمی‌تر از نسخهٔ زندهٔ مشاهده‌شده.
- `python3 scripts/build_release.py && python3 scripts/verify_release_safety.py`: ZIP بازتولیدپذیر از کل سورس و تطابق فایل‌ها/نسخه‌ها/CRC/SHA. خروجی نامزد در `public/` فقط برای تست محلی ساخته شد؛ فایل‌های `public/` که از پیش در Git دنبال می‌شدند پس از تست بازگردانده شدند و ZIP نامزد commit نمی‌شود.
- [GitHub Actions، اجرای `36227996593`](https://github.com/emeliijaddd-png/alookhor-update-publisher/actions/runs/36227996593): در **WordPress 6.8 + WooCommerce 10.2.0 واقعی** با MySQL موقتی و HTTP محلی، نصب/فعال‌سازی نامزد و افزونهٔ ووکامرس، افزودن سه محصول ساده در درخواست‌های جدا، پیشنهاد محصول متغیر، انتخاب واقعی گزینه و افزودن آن به‌عنوان ردیف چهارم، کوکی/نشست مهمان، SSR صفحهٔ سبد، تغییر تعداد بیش از ۲ و حذف در درخواست‌های تازه پاس شد. نسخهٔ WordPress/WooCommerce و قالب سایت تولیدی در این آزمایش استفاده نشد؛ هیچ سفارش یا درخواست POST به سایت زنده انجام نشد. روی push شاخه، `build` و `cart-wordpress` هر دو سبز بودند؛ `deploy` و `diagnose` اجرا نشدند. همین تست روی tag دروازهٔ لازمِ قبل از deploy است.
- `npm exec --yes --package=@php-wasm/cli -- php-wasm-cli ...`: نحو PHP تغییرات و قراردادها در sandbox بررسی شد؛ GitHub Actions با PHP بومی تمام فایل‌ها را lint می‌کند. هنوز آزمون مرورگر واقعی با قالب و کش سایت، هویت فایل‌های نصب‌شده و رد ZIP خراب **هنگام اجرای آپدیت واقعی روی staging** انجام نشده است.

## مانع «آمادهٔ نصب» و گام بعدی

**هنوز دکمهٔ Update یا Merge PR را نزنید.** انتشار با push این شاخه خودکار نیست؛ `release.json` عمداً `draft` است و workflow فقط build/test می‌کند. افزونهٔ فعال 405 مانیفست GitHub **شاخهٔ دیگری** را می‌خواند؛ push این PR آن مانیفست را تغییر نمی‌دهد. `main` نیز هنگام بررسی نسخهٔ متفاوت/درخت ناقص و workflow استقرار پرخطر داشته است. بنابراین نشان‌دادن گزینهٔ نصب از همین شاخه بدون تطبیق کانال و بسته، نادرست خواهد بود.

برای اعلام آماده‌بودن واقعی: نسخهٔ فعال و هویت فایل‌های نصب‌شده را فقط‌خواندنی چک کنیم؛ فراتر از آزمون HTTP محلی، با **قالب/کش واقعی و مرورگر** چهار عمل افزودن/تعداد/حذف/پیشنهاد متغیر و نشست مهمان را در محیط جدا از تولید بررسی کنیم؛ رد ZIP دستکاری‌شده در مسیر نصب را ببینیم؛ سپس بستهٔ همین GitHub را با SHA نهایی روی **کانال فعلیِ تنظیم‌شده** (نه مانیفست/ZIP نسخهٔ قدیمی یا mutable ناهمخوان) قابل دریافت کنیم و به‌طور مستقل بررسی کنیم. تنها بعد از پاس‌شدن این دروازه‌ها نسخه‌ای بالاتر از 405/411 برای کلیک نهایی مالک پیشنهاد می‌شود. این شاخه هیچ سفارش، تست POST روی سایت، نصب یا انتشار تولیدی انجام نداده است.
