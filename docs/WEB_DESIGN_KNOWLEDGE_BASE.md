## ۱️⃣ اصول طراحی بصری و Grid

### قوانین طلایی
- **سلسله‌مراتب بصری (Visual Hierarchy):** مهم‌ترین محتوا = بزرگ‌ترین/پرکنتراست‌ترین عنصر. چشم کاربر باید در ۳ ثانیه اول مسیر مشخصی را دنبال کند.
- **فضای سفید (White Space):** بخشی از طراحی است، نه فضای خالی. رابط‌های «آرام» ۲۰۲۶ با فضای سفید و کاهش شلوغی شناخته می‌شوند.
- **قانون ۸pt Grid:** فاصله‌ها و ابعاد مضربی از ۴ یا ۸ پیکسل (4, 8, 12, 16, 24, 32, 48, 64...).
- **حداکثر ۲ فونت، حداکثر ۳ وزن فونت** در هر صفحه.
- **قانون ۶۰-۳۰-۱۰ رنگ:** ۶۰٪ رنگ غالب، ۳۰٪ رنگ ثانویه، ۱۰٪ رنگ تاکیدی (Accent).
- **تعداد آیتم منو: ۵ تا ۷ مورد.** هر آیتم اضافه = بار شناختی بیشتر و تصمیم‌گیری سخت‌تر.
- **ثبات (Consistency):** دکمه‌ها، فاصله‌ها و آیکون‌ها در تمام صفحات یکسان باشند.

### سیستم Grid مدرن
```
Desktop:  12 ستون، gap 24px، container max-width 1200-1440px
Tablet:   8 ستون، gap 16-20px
Mobile:   4 ستون، gap 12-16px، حاشیه 16-20px
```
- **CSS Grid** برای چیدمان کلی، **Flexbox** برای اجزای درون یک بعد.
- از **CSS Logical Properties** استفاده کن (به‌جای `margin-left/right` از `margin-inline-start/end`) — پشتیبانی RTL خودکار می‌شود.

### روندهای ۲۰۲۶ (طبق تحقیقات Envato/Figma/FireArt)
- 🎯 **رابط‌های آرام (Calm Interfaces):** کاهش بار شناختی، اولویت با وضوح ذهنی به‌جای جلوه‌های نمایشی.
- 🤖 **AI شفاف:** اگر شخصی‌سازی هوش مصنوعی داری، کاربر باید ببیند «چرا این پیشنهاد را می‌بیند» و بتواند آن را override کند.
- 📐 **Brutalism لمسی:** هندسه تیز، حاشیه‌های 1px، حذف سایه‌های blur — عمق با لایه‌بندی و کنتراست ساخته می‌شود.
- ✍️ **تایپوگرافی جنبشی:** فونت‌های viewport-scaled به‌جای تصاویر Hero سنگین.
- ♻️ **وب پایدار:** کد سبک‌تر، تصاویر بهینه، هاست کم‌کربن.
- 🤖 **MX (Machine Experience):** سئو برای عامل‌های AI — HTML معنایی و ساختار داده از الزامات دیده‌شدن در جواب‌های AI شده است.

## ۲️⃣ UX و روانشناسی کاربر

### اصول علمی
| اصل | تعریف | کاربرد |
|-----|-------|--------|
| **قانون فیته** | زمان واکنش ∝ اندازه/فاصله هدف | دکمه‌های مهم = بزرگ و نزدیک |
| **قانون هیک** | زمان تصمیم ∝ تعداد گزینه‌ها | منو را ساده نگه دار |
| **الگوی F/Z** | مسیر اسکن چشم | محتوای مهم را اولین خط قرار بده (در RTL: سمت راست) |
| **اثر زیبایی‌شناختی** | طراحی زیبا = تحمل خطای بیشتر | زیبایی = اعتماد = تبدیل |
| **Pre-frontal Cortex Overload** | کاربر در هر لحظه یک تصمیم می‌گیرد | مراحل را بشکن |
| **اعتماد = شفافیت** | قیمت، سیاست، منبع مشخص | برای رسانه حیاتی است |

### قواعد تعامل (Interaction)
- **Micro-interactions:** بازخورد فوری برای هر عمل کاربر (hover، کلیک، لودینگ). حرکت باید «توضیح‌دهنده» باشد نه «نمایشی».
- **حالت‌های خالی (Empty States):** هیچ صفحه خالی بدون راهنما نباشد.
- **مدیریت خطا:** پیام خطا = چه شد + چرا + چگونه حل شود. هرگز فقط «خطا رخ داد».
- **Dark Patterns ممنوع:** تایید ۲ مرحله‌ای پنهان، اشتراک سخت‌اللغو، هزینه پنهان — تخلف اخلاقی + جریمه قانونی (در اتحادیه اروپا و آمریکا).
- **Navigation آویزش (Sticky):** کاربر هرگز نباید «گم» شود. جستجو همیشه در دسترس.

### متریک‌های موفقیت UX
- Time to First Interaction (TTI)
- Task Success Rate
- Bounce Rate / Dwell Time
- System Usability Scale (SUS) — بالای ۶۸ = بالای میانگین

## ۳️⃣ تایپوگرافی — با تمرکز ویژه RTL فارسی 🔴

> ⚠️ این بخش برای الاخبار حیاتی است — سایت فارسی‌زبان است.

### قواعد عمومی
- **طول خط خواندنی:** ۵۰ تا ۷۰ کاراکتر (ایده‌آل: ~۶۵).
- **ارتفاع خط (line-height):** ۱.۴ تا ۱.۸ برای متن بدنه (فارسی: ۱.۷ تا ۲ چون حروف کشیده و اعراب دارد).
- **اندازه پایه:** ۱۶-۱۸px برای بدنه؛ حداقل ۱۲px برای متن‌های فرعی.
- **Contrast متن:** حداقل 7:1 برای متن اصلی رسانه‌ای (فراتر از حداقل WCAG یعنی 4.5:1).

### فونت‌های فارسی استاندارد ۲۰۲۶
| فونت | کاربرد | مجوز |
|------|--------|-------|
| **IRANSansX / IRANSans** | استاندارد صنعت | تجاری (نسخه‌های آزاد قدیمی موجود) |
| **Vazirmatn** | متن بدنه، متن باز | آزاد (OFL) — گزینه عالی متن‌باز |
| **Estedad** | مدرن، متغیر (Variable) | آزاد |
| **Yekan Bakh / Kalameh** | تیترها | تجاری |
| **Shabnam / Sahel** | بدنه | آزاد |
| **Noto Naskh Arabic** | پشتیبان گوگل | آزاد |

### قواعد فنی RTL
1. **`<html dir="rtl" lang="fa-IR">`** — الزامی. بدون این، خوانندگان صفحه، موتور جستجو و مرورگر گیج می‌شوند.
2. **فارسی ۳-۴pt بزرگ‌تر:** خط فارسی در همان سایز لاتین کوچک‌تر رندر می‌شود؛ سایز فونت را افزایش بده.
3. **اعداد:** فارسی از ارقام فارسی (۰۱۲۳۴۵۶۷۸۹) استفاده می‌کند؛ اعداد لاتین داخل متن فارسی همیشه LTR می‌مانند.
4. **متن دوجهته (Bidi):** آدرس، ایمیل، URL و کد داخل متن فارسی باید با `dir="ltr"` یا `unicode-bidi: isolate` ایزوله شوند.
5. **آینه‌سازی کامل UI:** منو، ناوبری، دکمه‌های قبلی/بعدی، breadcrumbs — همه آینه شوند. اما:
   - دکمه‌های پخش رسانه (play) هرگز آینه نمی‌شوند
   - اسلش (`/`) آینه نمی‌شود
   - آیکون‌های جهت‌دار باید منطقی آینه شوند، آیکون‌های فیزیکی (ساعت) نه
6. **CSS Logical Properties:**
```css
/* ❌ قدیمی */            /* ✅ مدرن و RTL-ready */
margin-left: 16px;   →    margin-inline-start: 16px;
padding-right: 24px; →    padding-inline-end: 24px;
text-align: right;   →    text-align: start;
left: 0;             →    inset-inline-start: 0;
```
7. **بارگذاری فونت:** فقط WOFF2 (با subset فارسی)، `font-display: swap`، preload فونت اصلی.
8. **جداشدگی حروف (Ligature):** فونت باید اتصال حروف فارسی را درست نمایش دهد — با فونت لاتین روی متن فارسی، حروف جدا می‌شوند (مشکل رایج).
9. **نیم‌فاصله (ZWNJ):** «می‌خواهم» نه «میخواهم» — استاندارد نگارشی فارسی، روی SEO هم اثر دارد.

## ۴️⃣ رنگ و کنتراست

### پالت مصوب الاخبار (Burgundy/Gold)
```css
--color-bg-dark:      #0D0510;   /* پس‌زمینه اصلی */
--color-bg-panel:     #1C1024;   /* پنل‌ها */
--color-bg-overlay:   rgba(33,20,38,.75);  /* هدر شیشه‌ای */
--color-accent-gold:  #D49A2E;   /* طلایی اصلی */
--color-accent-bright:#E8B84A;   /* طلایی روشن */
--color-text-light:   #F5F3F0;   /* متن روشن */
--color-text-muted:   #C8C2C9;   /* متن خاموش */
```

### قواعد کنتراست (WCAG 2.2 AA — الزام قانونی در بسیاری کشورها)
| نوع محتوا | حداقل نسبت |
|-----------|-----------|
| متن عادی | 4.5:1 |
| متن درشت (18pt+ یا 14pt bold) | 3:1 |
| اجزای UI و گرافیک | 3:1 |
| متن روی پالت الاخبار (تست کن!) | #F5F3F0 روی #0D0510 ≈ **17:1** ✅ عالی |

- ⚠️ طلایی #D49A2E روی تیره #1C1024 ≈ 6.2:1 ✅ برای متن لینک مناسب.
- ⚠️ متن خاموش #C8C2C9 روی #0D0510 ≈ 11:1 ✅.
- رنگ نباید **تنها** حامل معنا باشد (مثلاً خطا فقط قرمز نباشد — آیکون + متن هم باشد).
- **Dark Mode:** پس‌زمینه واقعاً تیره (نه خاکستری نیمه‌روشن) = مصرف باتری کمتر در OLED + پایداری وب.

## ۵️⃣ سئوی فنی (Technical SEO) — نسل ۲۰۲۶

### ستون‌های سه‌گانه سئو (طبق تحلیل الگوریتمی ۲۰۲۶)
1. **ربط و نیّت (Intent Relevance)** — ستون اول: صفحه باید *نیّت جستجو* را پاسخ دهد، نه فقط کلمه کلیدی را داشته باشد.
2. **اقتدار (Authority)** — بک‌لینک باکیفیت + سیگنال برند.
3. **سلامت فنی (Technical Health)** — ایندکس‌پذیری، سرعت، بدون تکراری.

### E-E-A-T (پاییه اعتماد گوگل)
- **Experience** — تجربه واقعی نویسنده از موضوع
- **Expertise** — تخصص (صفحه نویسنده، سوابق)
- **Authoritativeness** — استناد خارجی، ذکر برند در منابع معتبر
- **Trustworthiness** — HTTPS، اطلاعات تماس واقعی، سیاست تحریریه، تاریخ انتشار/به‌روزرسانی

برای **سایت خبری** E-E-A-T حیاتی‌ترین فاکتور است — گوگل رسانه‌ها را با سخت‌گیرانه‌ترین معیار قضاوت می‌کند.

### AEO — سئو برای عامل‌های هوش مصنوعی (روند ۲۰۲۶)
- HTML معنایی: `<article>`, `<nav>`, `<main>`, `<time>`, `<figure>`
- **Schema.org کامل:** `NewsArticle`, `Organization`, `BreadcrumbList`, `Person`
- پاسخ مستقیم و ساخت‌یافته در ابتدای محتوا (برای Featured Snippet و AI Overview)
- FAQ با نشانه‌گذاری (بدون اسپم)

### چک‌لیست سئوی فنی
```
□ canonical برای هر صفحه (جلوگیری از محتوای تکراری)
□ sitemap.xml خودکار + robots.txt درست
□ title منحصربه‌فرد 50-60 کاراکتر + meta description 140-160 کاراکتر فارسی
□ H1 فقط یکی، سلسله H2/H3 منطقی (ساختار خبری)
□ URL فارسی کوتاه و خوانا / یا لاتین ترجمه‌شده (هر دو قابل قبول، ثبات مهم است)
□ alt توصیفی برای همه تصاویر خبری
□ لینک‌سازی داخلی موضوعی (Topic Clusters)
□ خروجی RSS فعال و کامل
□ صفحه نویسنده + بیو برای هر خبرنگار
□ تاریخ انتشار + به‌روزرسانی با <time datetime="...">
□ HTTPS + HSTS
□ بدون خطای 404 داخلی، بدون redirect زنجیره‌ای
□ hreflang اگر چندزبانه می‌شوی
```

## ۶️⃣ Core Web Vitals و کارایی 🔴

### اهداف عددی (۷۵صدک (75th percentile) کاربران واقعی)
| متریک | می‌سنجد | خوب | نیاز به بهبود | بد |
|-------|---------|------|----------------|-----|
| **LCP** | سرعت بارگذاری بزرگ‌ترین عنصر | ≤2.5s | 2.5-4s | >4s |
| **INP** | پاسخ‌دهی به تعامل | ≤200ms | 200-500ms | >500ms |
| **CLS** | پایداری بصری | ≤0.1 | 0.1-0.25 | >0.25 |

**واقعیت ۲۰۲۶:** صفحات رتبه ۱ حدود ۱۰٪ بیشتر از رتبه ۹ از Core Web Vitals عبور می‌کنند — در برابری محتوا، CWV برنده را تعیین می‌کند.

### اولویت‌بندی بهینه‌سازی (به‌ترتیب اثر)
1. 🖼️ **تصاویر** — بزرگ‌ترین عامل کندی: WebP/AVIF، سایز درست، `loading="lazy"` زیر fold، `fetchpriority="high"` برای تصویر Hero، `width/height` مشخص (ضد CLS)
2. ⚡ **JavaScript** — بزرگ‌ترین عامل INP: حذف اسکریپت‌های بی‌استفاده، defer غیربحرانی، تقسیم کد
3. 🗄️ **کش** — Page cache + Object cache (Redis) + Browser cache با headers درست
4. 🌐 **CDN** — Cloudflare یا مشابه؛ فاصله جغرافیایی سرور ایران → کاربر حیاتی است
5. 📐 **رزرو فضا** — ابعاد تصویر/ویدئو/تبلیغ از قبل تعیین شود (CLS)
6. 📦 **Minify** CSS/JS + Brotli/Gzip
7. 🏠 **هاست** — HTTP/2 یا HTTP/3، PHP 8.2+ برای وردپرس

### ابزار اندازه‌گیری
- **Google Search Console** (دیتای کاربر واقعی — ملاک گوگل)
- PageSpeed Insights / Lighthouse
- WebPageTest (تحلیل waterfall)
- Chrome UX Report (مقایسه با رقبا)

## ۷️⃣ دسترسی‌پذیری — WCAG 2.2 (سطح AA هدف)

### چهار اصل POUR
- **Perceivable** قابل‌ادراک: متن جایگزین، کنتراست کافی، قابل‌تطبیق
- **Operable** قابل‌اجرا: کیبورد، زمان کافی، بدون تشنج‌آوری
- **Understandable** قابل‌فهم: خوانا، قابل‌پیش‌بینی، کمک در خطا
- **Robust** مقاوم: HTML معنایی سازگار با فناوری‌های کمکی

### چک‌لیست ضروری (جدیدترین‌های WCAG 2.2)
```
ساختار:
□ <html lang="fa-IR" dir="rtl">
□ یک H1 در صفحه، سلسله منطقی تیترها
□ HTML معنایی (نه div برای دکمه!)
□ لینک «پرش به محتوا» (Skip to content)

کیبورد و فوکوس:
□ همه عملکردها با کیبورد قابل انجام
□ نشانگر فوکوس همیشه مرئی (outline واضح)
□ ترتیب Tab منطقی (در RTL: از راست به چپ!)
□ focal عنصر زیر هدر sticky پنهان نشود (معیار 2.4.11 جدید)
□ اندازه هدف کلیک حداقل 24×24px (معیار 2.5.8 جدید)

دیداری:
□ کنتراست 4.5:1 متن / 3:1 UI
□ متن تا 200% بزرگ‌شونده بدون خرابی
□ Reflow: در عرض 320px اسکرول افقی نباشد
□ رنگ تنها حامل معنا نباشد

چندرسانه‌ای:
□ alt توصیفی برای تصاویر خبری (خبر = چه کس، چه کجا، چه اتفاقی)
□ زیرنویس برای ویدئو
□ محتوای متحرک >5 ثانیه قابل توقف باشد

فرم‌ها:
□ label واقعی (نه placeholder به‌جای label!)
□ خطا با متن توضیح داده شود
□ احراز هویت بدون محدودیت شناختی (معیار 3.3.8 جدید)

پویا:
□ پیام‌های status با aria-live اعلام شوند
□ ARIA فقط برای پر کردن خلأ، نه جایگزین HTML معنایی
```

**چرا مهم است؟** ~۱۶٪ جمعیت معلولیت دارند + معیار قانونی (ADA، EAA، ماده ۹ دستورالعمل‌های داخلی) + هم‌پوشانی ۹۰٪ با سئو.

## ۸️⃣ طراحی موبایل‌محور (Mobile-First)

- **رویکرد:** طراحی از ۳۶۰px شروع شود و به بالا رشد کند — نه برعکس.
- **قاعده انگشت:** حداقل ۴۸×۴۸px برای اهداف لمسی اصلی (پیشنهاد قوی‌تر از حداقل 24px WCAG).
- **Hover در موبایل وجود ندارد** — هیچ عملکرد حیاتی نباید فقط در hover باشد.
- **موبایل مثل اپ:** تعامل بدون رفرش (AJAX)، منوی کشویی off-canvas، ویجت بازشونده.
- **منوی همبرگری:** در دسترس در هر لحظه اسکرول.
- **لوگو کوچک‌شونده هنگام اسکرول** (مثلاً 200px → 40px در حالت sticky).
- **AMP مرده است (۲۰۲۶):** HTML استاندارد بهینه‌شده همان نتیجه یا بهتر را می‌دهد.

## ۹️⃣ طراحی سایت خبری (Editorial Design) — هسته الاخبار

### ساختار صفحه اصلی
```
┌─────────────────────────────────────┐
│ Top Bar (پشتیبانی/پیام/تلفن) ← موجود در الاخبار │
│ هدر اصلی + منوی کپسولی ← موجود (Sticky rail) │
├─────────────────────────────────────┤
│ HERO: ۱-۲ خبر اصلی (تصویر بزرگ + تیتر بولد) │
│ + Kicker (سرفصل موضوعی) + تایم‌استمپ تازگی │
├─────────────────────────────────────┤
│ ردیف‌های موضوعی (سیاسی/اقتصادی/ورزشی...)   │
│ هر بخش: ۱ خبر اصلی + چند خبر فرعی        │
├─────────────────────────────────────┤
│ پرخواننده‌ترین‌ها / پیشنهاد سردبیر         │
├─────────────────────────────────────┤
│ فوتر کامل + لینک‌های حقوقی               │
└─────────────────────────────────────┘
```

### قواعد طلایی رسانه‌ای
- **Scan → Dwell → Trust:** خواننده باید بتواند اسکن کند، مکث کند، اعتماد کند.
- **دکمه «بارگذاری بیشتر» بهتر از اسکرول بی‌نهایت** — فوتر و لینک‌های حقوقی دیده می‌شوند.
- **قالب مقاله:** استندفرست (خلاصه زاویه دید) در ابتدا، نقل‌قول برجسته (pull-quote)، گالری داخل متن، دکمه‌های اشتراک‌گذاری sticky.
- **وبلاگ زنده (Live Blog):** برچسب‌های رنگی به‌روزرسانی + خط زمانی ثابت.
- **حداکثر ۳ بنر تبلیغاتی در یک تحقیق ۳۰۰۰ کلمه‌ای** — ۸ تبلیغ = خصومت با خواننده.
- **تبلیغ native:** برچسب شفاف «تبلیغ/حمایت‌شده» + پس‌زمینه متمایز = اعتماد حفظ می‌شود + الزام قانونی.
- **جای تبلیغ با نسبت ابعاد ثابت رزرو شود** — پرش صفحه (CLS) هم خواننده هم تبلیغ را می‌کُشد.
- **صفحه نویسنده + صفحه تماس + سیاست تحریریه** = E-E-A-T رسانه‌ای.
- **جستجوی زنده همیشه در دسترس** — کاربر هرگز نباید احساس گم‌شدن کند.
- **تازگی را نشان بده:** تایم‌استمپ نسبی («۲ دقیقه پیش»)، برچسب «شروع» برای خبر فوری.
- **شخصی‌سازی اختیاری با کنترل:** صفحه اصلی بر اساس علاقه‌ها بازآرایی شود، ولی دکمه ریست/غیرفعال‌سازی شفاف باشد (روند ۲۰۲۶ + حفظ اعتبار تحریریه).

### مونتاژ ویدئو/پادکست
- پلیر با کنترل کامل (توقف، سرعت، زیرنویس)
- انتشار هم‌زمان در RSS پادکست
- صفحه اختصاصی هر برنامه با آرشیو

## 🔟 نرخ تبدیل (CRO)

- **CTA واضح:** یک عمل اصلی در هر صفحه؛ متن دکمه فعلی («مشاهده خبر») نه passiv («کلیک کنید»).
- **اعتمادساز:** لوگوی مراجع، آمار واقعی، دیدگاه کاربران.
- **Fricrion را حذف کن:** هر فیلد اضافه فرم = کاهش تبدیل. پرداخت/عضویت در کمترین مرحله.
- **متریک‌های رسانه‌ای:** نرخ اشتراک خبرنامه، زمان اقامت، صفحات/جلسه، نرخ بازگشت (Retention) روز ۱/۷/۳۰.
- **A/B تست** برای: تیترها (۵-فاکتوره: کنجکاوی، فوریت، فایده، ویژگی‌محور، شفافیت)، چیدمان Hero، محل CTA.
- **Paywall مؤدبانه:** پرامپت منفعت‌محور با شمارنده عادلانه — نه دیوار فوری.

## 1️⃣1️⃣ امنیت و اعتماد

### الزامات
```
□ HTTPS با TLS 1.2+ و HSTS
□ CSP (Content Security Policy) — ضد XSS
□ هدرهای امنیتی: X-Content-Type-Options, X-Frame-Options
□ فرم‌ها: CSRF token + rate limiting
□ رمز عبور: bcrypt/argon2، بدون محدودیت paste (WCAG 3.3.8)
□ به‌روزرسانی منظم وردپرس/افزونه/قالب
□ بکاپ خودکار خارج از سرور
□ لاگ و مانیتورینگ
□ سیاست حفظ حریم خصوصی + کوکی شفاف (GDPR-گونه)
```

### مدل موجود الاخبار (الگوی خوب) ✅
- استقرار atomic با «manifest آخر» — اگر هر مرحله شکست بخورد، مانیفست جلو نمی‌رود
- اعتبارات فقط در GitHub Secrets — هرگز در کد
- FTP محدود به Document Root ساب‌دامنه آپدیت
- نقش وردپرسی اختصاصی بدون `activate_plugins`
- گزارش تشخیصی ضدّاِسکرین‌شات در شاخه `publisher-status`

## 1️⃣2️⃣ وردپرس — بهترین شیوه‌ها

### کارایی
- **PHP 8.2+** و دیتابیس MariaDB/MySQL به‌روز
- کش چندلایه: Page Cache (WP Rocket/LiteSpeed) + Object Cache (Redis) + OPcache
- تصاویر: WebP/AVIF + lazy-load بومی وردپرس + اندازه‌های responsive (`srcset`)
- حذف افزونه‌های تکراری/بلااستفاده — هر افزونه = ریسک امنیتی + کندی
- `wp_enqueue_*` استاندارد، نه echo خام — به‌هم‌نخوردن وابستگی‌ها
- AJAX از `admin-ajax.php` به **REST API** منتقل شود (سریع‌تر، قابل‌کش) — الاخبار REST دارد ✅

### استاندارد کد پروژه الاخبار (رعایت‌شده — حفظ کن)
- ساختار شیءگرا با `includes/` + `assets/css|js` تفکیک‌شده ✅
- REST API اختصاصی (`alookhor-cc/v1/...`) ✅
- فایل‌های CSS ماژولار (header / hero / footer / categories جدا) ✅
- تغییرات با `release.json` نسخه‌دار و SemVer ✅
- اسکریپت ممیزی بصری (`header_visual_audit.py`) ✅ — الگوی کمیابی و عالی

### برای سایت خبری
- Schema `NewsArticle` کامل (headline, image, datePublished, dateModified, author)
- RSS full-text + فید بخش‌ها
- کش صفحه برای کاربر مهمان = سرعت رسانه‌ای
- Lazy-load تصاویر شاخص در آرشیوها
- جستجوی سرور-ساید (نه فقط client-side) برای آرشیو بزرگ
