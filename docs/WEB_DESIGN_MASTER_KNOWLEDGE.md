# 📘 دانش جامع طراحی وب و سئو — مرجع تیم طراحی ALOOKHOR

> **نسخه:** 1.0.0 | **تاریخ تدوین:** 2026-09-06
> **منظور:** این سند، مغز جمعی «تیم طراحی وب» ماست — جمع‌بندی استانداردها و بهترین تجربه‌های جهانی در طراحی، تجربه کاربری، سئو، پرفورمنس، دسترس‌پذیری و تبدیل، تنظیم‌شده برای وب فارسی (RTL) و پروژه ALOOKHOR. قبل از هر طراحی یا تغییری، این چک‌لیست مرور می‌شود.

---

## بخش ۱ — استراتژی و شناخت (پیش از طراحی)

### 1.1 شناخت مخاطب
- تحلیل رفتار، هدف، ترجیحات و جمعیت‌شناسی کاربر؛ ساخت Persona قبل از هر تصمیم طراحی.
- قانون ۵ ثانیه: کاربر باید در چند ثانیه اول (مخصوصاً موبایل) بفهمد کسب‌وکار چیست، برای کیست و قدم بعدی چیست.
- هر صفحه دقیقاً **یک هدف مشخص** دارد؛ بدون ازدحام CTA و بدون اکشن پنهان.

### 1.2 معماری اطلاعات (IA)
- سلسله‌مراتب محتوا: مهم‌ترین‌ها در اولویت دید (Above the Fold)، بقیه در دسترس اما بدون شلوغی.
- ناوبری قابل پیش‌بینی و ساده، نه «باهوش»؛ حداکثر ۵–۷ آیتم منوی اصلی (قانون حد انتخاب / Hick's Law).
- ساختار URL تمیز، منطقی و کوتاه؛ Breadcrumb برای عمق بیش از دو سطح.
- صفحات کلیدی: خانه، دسته‌بندی‌ها، خدمات جداگانه (نه یک پاراگراف بلند)، درباره، تماس، سوالات متداول (FAQ = طلای تبدیل و سئو).

### 1.3 سفر کاربر و فانل
- طراحی User Flow قبل از Wireframe؛ هرس مسیر تا خرید/تماس حداکثر ۳ کلیک.
- نقاط تماس اعتماد در تمام مسیر: Social Proof، نظرات واقعی، نشان‌های امنیتی، قیمت شفاف یا راهنمای قیمت.

## بخش ۲ — اصول طراحی رابط و تجربه کاربری (UI/UX)

### 2.1 اصول بنیادین
1. **کارکرد مقدم بر زیبایی** — وقاحت ظاهری هرگز هزینه قابلیت استفاده نشود؛ کلاریتی به جای دکوراسیون.
2. **سادگی و سلسله‌مراتب بصری**: سایز برای اهمیت، پالت محدود ۳–۵ رنگ، سیستم فاصله‌گذاری ۸px Grid، فضای سفید آگاهانه (Whitespace).
3. **یکنواختی (Consistency)**: پالت رنگ، تایپوگرافی، فاصله‌ها، استایل دکمه‌ها و لحن محتوا در کل سایت یکسان — تحقق با Design System و Atomic Design (اتم ← مولکول ← ارگانیسم ← قالب ← صفحه).
4. **قراردادهای وب (Conventionality)**: منو بالا، لوگو بالا-راست در سایت‌های RTL، دکمه شبیه دکمه، لینک با واکنش Hover، آیکون سبد مثل سبد رفتار کند.
5. **Recognition over Recall**: گزینه‌ها را نشان بده، از حافظه کاربر سوال نپرس؛ دراپ‌داون بهتر از فیلد خالی، Autocomplete بهتر از جستجوی خالی.
6. **بازخورد و میکرواینترکشن**: Hover، لودینگ، پیام موفقیت/خطا، انیمیشن‌های ظریف — سیستم باید همیشه «حرف بزند».
7. **اصلاح خطا و فرم‌ها**: لیبل واضح، کمترین فیلد اجباری، Autocomplete، پیام‌های اعتبارسنجی کمک‌کننده (نه صرفاً قرمز)، Confetti/تایید پس از موفقیت.
8. **اصل دسترس‌پذیری از روز اول** — بازسازی بعدی ۱۰ برابر گران‌تر است.

### 2.2 روانشناسی بصری و نورولوژی طراحی
- الگوی خوانش F و Z؛ قانون سوم‌ها؛ Fitts's Law (هدف‌های لمسی بزرگ و نزدیک)؛ نزدیکی Gestalt.
- تئوری رنگ در رفتار: طلایی/مشکی = لوکس و اعتماد؛ Burgundy/Gold (کمبو فعلی ALOOKHOR) = اصالت و وقار.
- اثبات اجتماعی انواعش: امتیاز، نظر، لوگوی مشتریان، تعداد فروش، داستان مشتری.
- کمیابی و فوریت اخلاقی (موجودی واقعی، نه Fake Scarcity).

### 2.3 موبایل‌فرست (غیرقابل مذاکره)
- بیش از ۶۰٪ ترافیک موبایل است؛ طراحی از کوچک‌ترین صفحه شروع شود.
- المان‌های مهم با یک دست قابل استفاده (Thumb Zone)؛ دکمه‌ها و اهداف لمسی حداقل ۴۴×۴۴ پیکسل.
- جایگزینی Hover با Tap/Focus؛ منوهای پیچیده ← آکاردئون/کشویی؛ تست روی CPU ضعیف موبایل.
- Sticky CTA (تماس/خرید/مشاوره) در موبایل اغلب برنده است.

## بخش ۳ — تایپوگرافی و هویت بصری فارسی (تخصص RTL)

### 3.1 تایپوگرافی فارسی
- فونت‌های استاندارد وب فارسی: **وزیرمتن، استعداد، دانا، ایران‌سنس، شبنم، ساحل، گندم** — انتخاب بر اساس شخصیت برند (برای لوکس: وزن‌های Light/Regular با تراکم مناسب).
- حداکثر ۲ خانواده فونت و ۳–۴ وزن؛ هر وزن اضافه = هزینه پرفورمنس. فونت را خودکار Subset کنید (فقط گلیف‌های فارسی/لاتین لازم).
- `font-display: swap`، preload برای فونت‌های Critical، WOFF2 حتماً.
- اندازه متن پایه حداقل ۱۶px، ارتفاع خط ۱.۷–۱.۹ برای فارسی (حروف فارسی ارتفاع بصری بیشتری نیاز دارند)، طول خط ایده‌آل ۵۰–۷۵ کاراکتر.
- اعداد: در متن فارسی، اعداد فارسی (۰۱۲۳...) یا لاتین — یکدست در کل سایت، با توجه به فونت انتخابی.

### 3.2 قواعد RTL
- آینه‌ای کردن کامل چیدمان: `dir="rtl"`، استفاده از CSS Logical Properties (`margin-inline-start` به جای `margin-left`).
- آیکون‌های جهت‌دار (فلش‌ها، Breadcrumb، اسلایدر) باید RTL شوند؛ آیکون‌های بی‌جهت (ساعت، تیک) ثابت می‌مانند.
- اعداد، تاریخ، قیمت و تلفن همیشه LTR داخل متن RTL (`direction: ltr; unicode-bidi: isolate` برای تلفن/ایمیل).
- اسلایدرها، استپرها، Progress Bar و جریان فرم‌ها باید راست‌به‌چپ حس شوند.

### 3.3 هویت ایرانی-اسلامی (در صورت تناسب برند)
- الگوهای هندسی **گِره (Girih)**، مقرنس، اسلیمی/ارابسک، ستاره ۸ و ۱۰ پر، روزت (گل مرکزی) — به‌صورت ظریف در دایوایدر، بک‌گراند کم‌رنگ یا حاشیه، نه شلوغی صفحه.
- پالت الهام‌گرفته از کاشی‌کاری ایرانی: فیروزه‌ای، لاجوردی، سرمه‌ای + طلایی؛ یا لوکس مینیمال فعلی: Black/Gold و Burgundy/Gold.

## بخش ۴ — پرفورمنس و Core Web Vitals (استاندارد ۲۰۲۶)

| متریک | چیست | آستانه سبز |
|---|---|---|
| **LCP** | رسم بزرگ‌ترین عنصر محتوایی | ≤ ۲.۵ ثانیه |
| **INP** | تأخیر پاسخ به تعامل | ≤ ۲۰۰ میلی‌ثانیه |
| **CLS** | پایداری بصری (پرش چیدمان) | ≤ ۰.۱ |
| **TTFB** | پاسخ سرور | ≤ ۰.۸ ثانیه |
| **FCP** | اولین رسم محتوا | ≤ ۱.۸ ثانیه |

### چک‌لیست پرفورمنس
- تصاویر: فرمت **AVIF/WebP**، سایز واقعی نمایشی (نه آپلود ۶۰۰۰px!)، `srcset` ریسپانسیو، Lazy Load زیر Fold، عرض/ارتفاع صریح برای جلوگیری از CLS.
- فونت: حداکثر ۲ خانواده، WOFF2، Subset، Preload، font-display: swap.
- اسکریپت‌ها: Minify، Defer/Async، حذف JS بلااستفاده، حداقل پلاگین (خصوصاً در وردپرس)، Code Splitting.
- CDN، کش مرورگر، کش سمت سرور (OPcache/Object cache)، Brotli/Gzip.
- Preconnect/DNS-Prefetch برای منابع ثالث؛ تصویر Hero را Preload کنید (LCP بحرانی).
- Critical CSS برای Above the Fold؛ تولید SSR/SSG در صورت امکان.
- داده واقعی (CrUX/Field Data) مهم‌تر از امتیاز آزمایشگاهی؛ بهینه‌سازی LCP از ۴ به ۲.۵ ثانیه تا ۱۵٪ افزایش تبدیل ثبت شده.
- بودجه پرفورمنس: مجموع صفحه ایده‌آل زیر ۱–۱.۵MB موبایل.

## بخش ۵ — سئوی تکنیکال

### 5.1 زیرساخت و ایندکس
- HTTPS اجباری (رایگان با Let's Encrypt)؛ HSTS؛ ریدایرکت ۳۰۱ نسخه‌های www/non-www و http→https به یک Canonical نهایی.
- `robots.txt` تمیز + **XML Sitemap** به‌روز + ثبت در Google Search Console و Bing Webmaster.
- Canonical روی هر صفحه؛ مدیریت پارامترها، فیلترهای فروشگاهی و صفحه‌بندی (rel=next/prev دیگر سیگنال نیست ولی ساختار منطقی لازم است).
- hreflang فقط اگر چندزبانه شود.
- موبایل‌فرست ایندکسینگ: محتوای موبایل = نسخه مرجع گوگل.

### 5.2 تگ‌ها و داده ساخت‌یافته
- Title یکتا: ۵۰–۶۰ کاراکتر، کلمه کلیدی نزدیک ابتدا + برند.
- Meta Description یکتا: ۱۵۰–۱۶۰ کاراکتر، دعوت به کلیک (CTR در رتبه اثر دارد).
- سلسله‌مراتب هدینگ: یک H1 در هر صفحه، سپس H2/H3 منطقی — بدون پرش.
- Alt توصیفی برای همه تصاویر محتوایی (هم سئو، هم دسترس‌پذیری).
- **Schema.org** با JSON-LD: `Organization`، `LocalBusiness`، `Product` (قیمت/موجودی/امتیاز)، `BreadcrumbList`، `FAQPage`، `Article`، `Review/AggregateRating`، `WebSite` + Sitelinks Search Box.
- Open Graph + Twitter Card برای اشتراک‌گذاری؛ تصویر OG اختصاصی ۱۲۰۰×۶۳۰.
- Core Web Vitals، مدیریت خطای ۴۰۴ (صفحه ۴۰۴ سفارشی با لینک‌های مفید)، ریدایرکت زنجیره‌ای ≤ ۱، لینک شکسته = صفر.

### 5.3 سئوی فروشگاهی (WooCommerce)
- URL دسته/محصول کوتاه و معنادار؛ خودداری از تاریخ در URL محصول.
- توضیحات محصول یکتا (هرگز کپی از تولیدکننده/رقیب)؛ اسکیما Product کامل با GTIN/برند.
- محصولات ناموجود: صفحه زنده بماند + پیشنهاد جایگزین + «موجود شد خبرم کن» (نه ریدایرکت کور به خانه).
- فیلتر فِسِت بدون تولید هزاران URL ایندکس‌شونده (noindex/Canonical استراتژیک).

## بخش ۶ — سئوی محتوا و E-E-A-T

- **محتوا همچنان پادشah است**: گوگل در ۲۰۲۶ رتبه را بر اساس رضایت جستجوگر، نیت کاربر (Search Intent)، اعتبار موضوعی و تعامل تعیین می‌کند — نه تطابق عبارتی صرف.
- **E-E-A-T**: تجربه واقعی، تخصص، اعتبار، اعتماد — نویسنده مشخص، صفحه «درباره»ی واقعی، منابع معتبر، آپدیت منظم.
- خوشه‌های موضوعی (Topic Cluster): صفحه ستونی + مقالات مرتبط با لینک‌سازی داخلی سیستماتیک.
- کلمات کلیدی طولانی (Long-Tail) با نیت مشخص؛ پرهیز از Keyword Stuffing.
- **AEO/GEO ۲۰۲۶**: ساختار محتوا برای Featured Snippet، AI Overviews و موتورهای پاسخ — پاسخ مستقیم کوتاه در ابتدای متن، لیست، جدول، FAQ.
- محتوای نازک (Thin) و تکراری (Duplicate) ممنوع؛ هر صفحه باید ارزش مستقل داشته باشد.
- تازگی محتوا: آپدیت دوره‌ای صفحات پول‌ساز.
- ویدئو و تصویر اختصاصی (نه استوک تکراری) برای جایگاه‌های بصری نتایج.

### سئوی محلی (برای کسب‌وکار داخل ایران)
- پروفایل کسب‌وکار گوگل (Google Business Profile) کامل و به‌روز؛ NAP (نام/آدرس/تلفن) یکدست در کل وب.
- نظرات واقعی مشتری + پاسخ به آن‌ها؛ صفحات فرود محلی برای شهرهای هدف؛ نقشه و مسیر دسترس.
- اینماد/نماد اعتماد الکترونیکی برای فروشگاه ایرانی: هم اعتماد کاربر، هم سیگنال اعتبار.

## بخش ۷ — دسترس‌پذیری (Accessibility — WCAG 2.2)

- کنتراست رنگ: متن عادی ≥ ۴.۵:۱، متن بزرگ ≥ ۳:۱، عناصر UI ≥ ۳:۱.
- ناوبری کامل با کیبورد؛ Focus Visible همیشه؛ Skip Link «پرش به محتوا».
- ARIA Role/Label صحیح؛ HTML سمانتیک (`header/nav/main/article/footer`)؛ Screen Reader تست شود.
- Alt برای تصاویر، Caption/زیرنویس برای ویدئو؛ هرگز اطلاعات فقط با رنگ منتقل نشود.
- فرم‌ها: لیبل مرتبط، خطای خوانا، بدون Captcha صرفاً تصویری.
- اندازه هدف لمسی ≥ ۲۴×۲۴ (ترجیحاً ۴۴px)؛ انیمیشن با `prefers-reduced-motion` کنترل شود.
- **مزیت مضاعف:** دسترس‌پذیری = سئوی بهتر + مخاطب بیشتر + اعتبار برند.

## بخش ۸ — امنیت، حریم خصوصی و قانون‌گذاری

- HTTPS/HSTS، آپدیت منظم هسته/پلاگین/قالب وردپرس، بکاپ خودکار روزانه + تست بازیابی.
- هاردنینگ وردپرس: مخفی‌سازی یوزرنیم ادمین، محدودیت تلاش ورود، WAF، حذف پلاگین/قالب غیرفعال، غیرفعال کردن XML-RPC در صورت عدم نیاز، دسترسی حداقلی (Least Privilege).
- ضداسپم فرم‌ها: Honeypot/reCAPTCHA؛ اعتبارسنجی سمت سرور برای همه ورودی‌ها.
- Content-Security-Policy و هدرهای امنیتی (X-Frame-Options, X-Content-Type-Options, Referrer-Policy).
- حریم خصوصی: صفحه قوانین و حریم خصوصی، بنر کوکی در صورت ترکینگ (GDPR/قوانین محلی)، حداقل‌گری داده (Data Minimization).
- تراکنش: درگاه پرداخت معتبر، عدم ذخیره اطلاعات کارت روی سایت، نشان امنیتی در چک‌اوت.

## بخش ۹ — نرخ تبدیل (CRO) و رشد

- یک CTA اصلی در هر صفحه، بالای Fold، با رنگ متضاد و متن عمل‌محور («ثبت سفارش» بهتر از «ارسال»).
- تماس بدون اصطکاک: تلفن/واتساپ در هدر و فوتر، فرم کوتاه، دکمه شناور در موبایل.
- چک‌اوت: سبد←پرداخت در کمترین قدم، خرید مهمان، نمایش هزینه ارسال زودهنگام (علت اول رها کردن سبد = هزینه پنهان).
- رهاکردن سبد (Cart Abandonment): ایمیل/پیامک یادآوری.
- A/B تست روی صفحات پول‌ساز؛ حداقل ۵ تست کاربردپذیری واقعی پیش از لانچ.
- Heatmap و Session Recording (Microsoft Clarity رایگان)؛ آنالیتیکس با تعریف Conversion و Funnel واقعی (GA4 + Search Console).
- چت آنلاین/چت‌بات برای سوالات پایه (استاندارد جدید ۲۰۲۶).
- ایمیل مارکتینگ: فرم خبرنامه با مشوق، Welcome Flow، پس‌خرید پیگیری.

## بخش ۱۰ — ترندهای ۲۰۲۶–۲۰۲۷ (آینده‌نگری)

1. شخصی‌سازی تطبیقی و موتورهای توصیه AI — حریم‌محور (Privacy-first Personalization).
2. بهینه‌سازی برای جستجوی AI و صفر-کلیک (AEO): سایت به‌عنوان «منبع پاسخ»، نه فقط مقصد کلیک.
3. میکرواینترکشن‌های هدفمند و Motion Design معنادار.
4. طراحی پایدار (Green Web): صفحات سبک‌تر = کربن کمتر + سرعت بیشتر.
5. رابط‌های صوتی و ژستی در حوزه‌های خاص؛ Zero-UI در افق.
6. طراحی اخلاقی (Ethical Design): شفافیت، بدون Dark Pattern، احترام به توجه کاربر.
7. مرز طراحی و مهندسی کدرمحور: Design Token، طراحی مستقیم در کد، کامپوننت‌های زنده.

## بخش ۱۱ — چک‌لیست نهایی پیش از انتشار هر صفحه (No-Excuses)

- [ ] هدف صفحه در ۵ ثانیه واضح است؛ یک CTA اصلی بالای Fold
- [ ] موبایل‌فرست: همه‌چیز با یک دست، متن خوانا، دکمه‌ها ≥ ۴۴px
- [ ] LCP ≤ ۲.۵s / INP ≤ ۲۰۰ms / CLS ≤ ۰.۱ (با داده واقعی)
- [ ] تصاویر WebP/AVIF + سایز درست + Lazy Load + Alt توصیفی
- [ ] فونت WOFF2 سبک، swap، RTL بی‌نقص (چیدمان/اعداد/آیکون‌ها)
- [ ] یک H1 + سلسله‌مراتب هدینگ درست؛ Title/Meta یکتا
- [ ] Schema مناسب (Product/FAQ/Org/...) تست‌شده در Rich Results
